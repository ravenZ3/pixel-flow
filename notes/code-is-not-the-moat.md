# The code is not the moat — what is, in 2026

## The honest question

I asked: *"is this even my project? we are using Claude to write the
nodes."*

That's a fair thing to ask and it deserves a real answer.

## What's actually mine vs the model's

Looking back at the session honestly:

**What the model wrote:** most of the lines of code. The node
executors, the agent loop, the API route, the share encoding, the
UI components. The majority of the file diffs.

**What I did, and only I could do:**

- Picked the project. Decided what to build.
- Noticed when something looked wrong before any test would have caught
  it (the white pipeline, the rainbow stripes, the agent making empty
  ImageInputs, the UI being too bright).
- Owned the direction. The model proposed five next steps every turn;
  I picked which one to actually pursue.
- Came up with the cinematic-preset thesis. The model had been pushing
  print-style aesthetics for ten turns; that's where it would have
  kept pushing without me.
- Made every taste call. "This is the wedge." "Add Posterize next."
  "Move the minimap." "Color too bright." None of those came from
  the model.

The code was the easy part. **Direction, taste, and noticing-things-
are-wrong are the hard parts, and those are mine.**

## The reframe

A founder in 2026 using AI to ship faster is still a founder. A
senior engineer using AI to write boilerplate they could write but
slower is still a senior engineer. The leverage isn't fake — it's
just the new tier of leverage available to anyone with direction.

The trade is: code becomes cheap, **judgment about what to code stays
expensive.**

## The warning hidden in the question

But there's a real worry buried inside *"we are using Claude to
write the nodes,"* and it's worth naming clearly.

**Anyone with $20/month and reasonable taste can clone the code in
about two weeks.** Maybe less. Every node, every UI choice, every
agent prompt I've written — replicable.

If "what we built" is the moat, the project is cooked. Someone
with a marginally better idea will outpace it.

So in 2026, for a project like this, the moat has to come from
things the model cannot do for me:

### 1. Speed of iteration on real user feedback

The model can write the next node in 5 minutes. It cannot tell me
*which* node I need without me observing real users using it. The
loop "ship → watch → adjust" is mine to run.

### 2. Taste / aesthetic judgment

The cinematic-preset idea was an act of taste. The next 50 product
decisions will be too. This is the part that compounds and that
doesn't transfer.

### 3. Content + audience

The viral reels. The community around remixable preset URLs. The
account that becomes the watering hole for cinematic-photo nerds.
None of this is code.

### 4. Specific recipes

The 50 carefully-tuned preset graphs. The hours spent dialing in
"Drive" until it actually looks like Drive. The eye for it. Anyone
can replicate the engine; replicating the recipe library takes
someone with the right eye and the time to use it.

### 5. Brand and trust

VSCO Cam, RNI Films — those preset brands took years of consistency
to earn trust. Hard to clone. Accruable, slowly.

## What this means concretely

The decision isn't *"can I build this?"* — yes, easily, with the
model.

The decision is **"am I willing to do the parts the model can't do?"**

Concretely:

- Am I willing to record and post 6 reels a week?
- Am I willing to spend 3 hours dialing in a Twilight preset until
  it actually looks like Twilight?
- Am I willing to read every piece of user feedback and respond?
- Am I willing to make 50 small taste calls a week without knowing
  if any of them are right?

If yes → the AI-writing-the-code doesn't matter, it's a real product.

If no → it's a great portfolio piece and a learning exercise, which
is also legitimate, just call it that and move on.

## The single rule that follows

**Don't compete on anything the AI can also do for the next person.**

The next person also has the AI. Compete on the parts that don't
transfer:

- Your specific eye
- Your specific obsession with a specific aesthetic
- The audience you build by being that person publicly
- The recipes nobody else has the patience to dial in

Code is cheap. Taste, audience, and patience are the new scarce goods.
